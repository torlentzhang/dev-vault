# 大前端知识库 · README

> 个人知识管理仓库，面向「前端 → Node 全栈」的系统化学习沉淀。大前端范畴涵盖：前端基础 / 框架 / 工程化 / Node 服务端 / DevOps。

## 一、笔记体系与采用理由

### 采用的体系

本知识库采用 **PARA 分区框架 + Zettelkasten（卡片盒）卡片方法 + Obsidian 双链 / MOC** 的混合体系：

- **PARA（Projects / Areas / Resources / Archives）**：用编号目录把内容按「项目 / 领域笔记 / 资源 / 归档」分区，让流动性的工作与长期沉淀的知识各归其位。
- **Zettelkasten（卡片盒笔记法）**：以「原子卡片」为基本单元，一张卡片只承载一个独立知识点（概念卡、文献卡、操作卡等），卡片之间通过双向链接相互连接，形成可生长的网络，而非线性文档堆。
- **Obsidian + 双链 / MOC**：以 Obsidian 为承载工具，用 `[[双向链接]]` 串联卡片，用 MOC（Map of Content，内容地图）作为入口与枢纽。

**目录角色约定（分层 MOC）**：`00-Index` 专放 MOC（内容地图），`02-Notes` 专放原子卡片，两类东西分开，编排难度直接砍半。MOC 用 `MOC-` 文件名前缀区分层级——`Index.md` 为顶层大地图，`MOC-前端基础.md` 为一级领域 MOC，全部平铺在 `00-Index`，不靠嵌套文件夹。「大 MOC 套小 MOC」即由此实现。**目前均为一级领域 MOC（共 5 个）；若某领域知识点过多，可改用 `MOC-领域-子主题.md` 表达二级，如 `MOC-前端-HTML.md`，按需扩展。**

### 采用这种体系的理由

1. **知识杂而广，需要结构化沉淀**：从前端转向 Node 全栈，要同时吸收语言、框架、工程化、服务端、DevOps 等多条线的知识，散落收藏容易遗忘、难以复用；分区 + 卡片能把碎片「安家」。
2. **原子卡片便于复用与连接**：Zettelkasten 强调「一张卡一个概念」，避免大笔记臃肿；当需要讲清一个主题时，把相关卡片用双链织起来即可，单卡还可被多个主题复用。
3. **PARA 让「流动」与「沉淀」分离**：项目（03）、日常（01）是流动的、会结束的；领域笔记（02）、资源（04）是长期沉淀；归档（99）是冷却的内容。边界清晰，检索成本低。
4. **双链 + MOC 形成知识网络**：线性文件夹只能「树状」归类，而知识本身是网状的。双链让卡片互相引用，MOC（00-Index）作为枢纽把分散的卡片聚成主题地图，越用越聪明。
5. **Git 同步保障安全与多端可用**：仓库接入 Git（含远程），既能版本回溯，也能在多台设备间同步；同时已通过 `.gitignore` 排除 WorkBuddy 等工作区元数据，避免无关内容入库。

## 三、使用规范（结构约定）

以下几条是经反复整理后确定的约定，新增内容时请遵循，避免结构再次失稳：

1. **目录职责一刀切**：`00-Index` 只放 MOC（入口 / 领域地图），`02-Notes` 只放原子卡片；两类东西分开，不混放。
2. **MOC 命名与分层**：领域 MOC 用 `MOC-领域.md`（如 `MOC-工程化.md`）；某一领域知识点过多时，可用 `MOC-领域-子主题.md` 表达二级（如 `MOC-前端-HTML.md`）。所有 MOC 平铺于 `00-Index`，不建嵌套文件夹。
3. **卡片命名**：原子卡片直接以概念命名，如 `corepack是什么.md`、`normalize与reset的区别.md`；不加 `MOC-` 前缀（前缀专属于地图）。
4. **卡片归属（单一归属）**：每张原子卡只被 **一个** MOC 链接，避免重复与边界模糊。归属以「卡片主语」为准：
   - 框架本体（Vue / React 原理、组件通信、状态管理）→ `MOC-框架`
   - 框架实践（如 Vue3 项目从 0 到 1 搭建）→ `MOC-框架`（主语是框架）
   - 纯构建工具原理（Vite / Webpack 配置、打包优化）→ `MOC-工程化`
   - 包管理 / 版本管理 / 本地规范（pnpm、corepack、nvm、ESLint）→ `MOC-工程化`
   - 运行时 / 服务端（事件循环、http、流、进程）→ `MOC-Node服务端`
   - HTML / CSS / JS / TS / 浏览器 / DOM → `MOC-前端基础`
   - CI-CD / 容器 / 部署 / 监控 → `MOC-DevOps`
5. **frontmatter 约定**：所有卡片与模板头部统一含 `type` / `tags` / `created` 三字段（concept / literature / howto / moc / daily / note 六种 type）。模板位于 `05-Templates`，新建笔记请基于对应模板。
6. **暂不互织**：当前阶段原子卡之间**暂不**建立双向链接（卡片 ↔ 卡片的网络）；MOC → 卡片 的链接已接通。等卡片积累到一定量、需要织网时再启用卡片间互链。
