# 安全区适配

## 适用场景
- **刘海屏 / 圆角屏**：状态栏、摄像头挖孔区域压住顶部内容。
- **底部 Home Indicator 横条**：底部固定的按钮、tabbar 被横条盖住或挤得太近。
- **被虚拟键盘遮挡的输入区域**：需要配合 VirtualKeyboard API（见步骤 ③）。

目标有两个，必须**同时**满足：让内容不被系统 UI 遮挡，**同时**让背景真正铺满全屏（而不是被系统自动内缩、四周留出白边）。

## 步骤

### 1. 先在 meta viewport 上加 `viewport-fit=cover` —— 这是前提
```html
<meta name="viewport" content="width=device-width, viewport-fit=cover">
```
不加这一步，后面所有 `env()` 都是白写：默认值 `auto` 会自动内缩、设备不进入「全屏布局」，`env()` 取到的是 `0`。

### 2. 用 `env(safe-area-inset-*)` 为各方向补内边距 / 外边距
```css
/* 底部固定按钮：安全区是在原有间距之外"额外增加"的距离 */
.tabbar {
  padding-bottom: 12px;                              /* 前置普通声明，作兜底 */
  padding-bottom: env(safe-area-inset-bottom, 0px);  /* 带兜底值 */
}
```
三个必须做到的细节：
1. **各方向分开写**：用 `padding` / `margin` **简写会把没写到的方向的值覆盖掉**（上面的 `padding-bottom` 就没了），所以要放在已有简写之后单独声明那一方向。
2. **写兜底值**：`env(safe-area-inset-bottom, 0px)` —— 变量取不到时退回 `0px`，而不是整条声明失效。
3. **保留一条前置普通声明**：不认 `env()` 的浏览器会整条丢弃该声明，前面那条普通声明能顶上。

四个方向都有对应变量：`safe-area-inset-top` / `-right` / `-bottom` / `-left`。

### 3.（可选）另外两组变量
- `safe-area-max-inset-*`：该方向安全区的**静态最大值**（不随界面状态变化）。
- `keyboard-inset-*`：虚拟键盘占用的尺寸，配合 **VirtualKeyboard API** 使用。

## 注意事项 / 踩坑
- **必须配 `viewport-fit=cover`**：WebKit 官方说明 —— 默认值 `auto` 会自动内缩、设备不进入「全屏布局」，所以在 iOS Safari 上这些 `env()` **取到的是 0**；只有 `cover` 才铺满屏幕，而此时才需要自己用 `env()` 把安全区补回来。
- **不能用 `padding` / `margin` 简写**：简写会覆盖其它方向已有的值，必须分开写。
- **历史坑 `constant()`**：只存在于 iOS 11 的首发版本，iOS 11.2 beta 起改为 `env()`；可以用 CSS 回退同时兼容，但**不应再作为主写法**。
