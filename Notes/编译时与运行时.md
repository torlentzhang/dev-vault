# 编译时与运行时

## 一句话定义
编译时是**代码变成可执行形式之前**、工具处理源码的阶段；运行时是**程序真正执行**的阶段。判断二者的唯一实用标准是「**求值时机**」——这件事是什么时候才确定的。（注意「运行时」另有一义：支撑程序运行的环境 / 运行库。）

## 要点

### 判据：求值时机，而不是背定义
- 编译时（compile time / build time）：此时能看到完整源码与静态信息，但结果被**固化进产物**
- 运行时（runtime）：此时才拿到真实数据、用户输入、运行环境

### 「运行时」是双义的（最大混淆源）
1. **阶段义**：与「编译时」相对的运行期（本卡主体）
2. **实体义**：支撑程序运行的**运行环境 / 运行库**——JS 的运行时是 V8，服务端的运行时是 Node（`MOC-Node` 里「Node 作为服务端运行时」用的是这个意思）

同一个词两种用法，读文章时先分清。

### build time 不是第三个概念
前端常说的「构建时 / 打包时」是「编译时」的一个实例——由 Vite / Webpack 这类 bundler 在构建阶段完成。

### 时机 = 能力边界
| 只能在编译期确定 | 只能在运行期确定 |
| --- | --- |
| 类型检查（TS） | 用户输入 / 交互 |
| tree-shaking、死代码消除 | API 数据 |
| 宏消除（`defineProps` 运行时不存在） | CSS 变量求值 |
| Sass 变量替换、auto-import 注入 | JS 表达式求值 |

工程倾向：**能在编译期确定的事，就别拖到运行时**——编译期不占用用户设备、更安全（类型 / 静态检查）、更适合优化。

### 会模糊边界的场景（别把二者想成绝对）
- **JIT / 运行时编译**：运行时才把代码编译成可执行形式。V8 把 JS 热点编译成机器码；Vue 完整版能在运行时编译字符串模板。这就是常被说成「运行时编译」的东西。
- **SSR / SSG**：构建时渲染 vs 运行时渲染，取决于页面何时生成。
- **动态 `import()`**：模块在运行时才确定加载。

## 我的理解 / 类比
编译时像**出厂前在工厂做的质检和预装**（能装好的都在厂里装好，用户拿到即成品）；运行时像**用户在家里实际使用**（才知道真实需求）。能在厂里解决的就不该留到用户手里——这解释了为什么前端工程化总想「把计算往编译期挪」（类型、tree-shaking、宏）。
