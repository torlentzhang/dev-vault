# 动态路由匹配

## 一句话定义
用 `:参数名` 占位符把"一类路径"映射到同一个组件，URL 里变化那一段被路由解析成 `params` 交给组件使用。

## 用于解决什么问题
没有占位符时，`/user/1`、`/user/2` 这类路径只能一条条注册，ID 有多少种就要写多少条路由；退回查询串传参，又会把本该属于路径的信息塞进 `?`，层级语义全丢。

## 要点
- 写法：`{ path: '/user/:id', component: User }`，`/user/123`、`/user/456` 都命中它，共用 `User` 组件。
- 取值：组合式 API 用 `useRoute().params.id`；Options API 用 `this.$route.params.id`。**`route.params` 的值永远是字符串**，后端 / 数据库要数字记得 `Number()` 转。
- 填值（编程式）：`router.push({ name: 'user', params: { id } })`——**`params` 必须配 `name`，配 `path` 会被静默忽略**（见 [[命名路由]]、[[编程式导航router.push]]）。
- 多段参数：`/user/:id/post/:pid` → `params = { id, pid }`。
- 进阶语法：`:id?` 可选；`:id(\\d+)` 正则限定只匹配数字（JS 字符串里反斜杠要转义，写成 `\\d`）。
- ⚠️ 同一组件切换不同参数时**不会重建**，生命周期钩子不重跑——这是 [[动态路由的组件复用问题]] 的坑。

## 我的理解 / 类比
像快递柜：柜子（组件）只有一套，`:id` 是格子号；号不同，取出的包裹（数据）不同，但柜子本身没换。
