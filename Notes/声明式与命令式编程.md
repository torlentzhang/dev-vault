# 声明式与命令式编程

## 一句话定义
命令式编程描述「**怎么做**」(how)——一步步给出改变状态的指令；声明式编程描述「**要什么**」(what)——只描述目标结果，把「怎么做」交给底层实现。二者不是非黑即白，而是抽象层级的连续谱，**声明式通常以命令式为底座**。

## 要点

### 判据
- 命令式：给过程 / 步骤 / 副作用（`for` 循环累加、手动 `appendChild`、jQuery 增删 DOM）
- 声明式：给目标 / 映射关系（`map` / `filter`、SQL、HTML、CSS、Vue 模板、React JSX）

### 不是二元对立（最容易被误解的点）
- 它是连续谱：同一件事可以在不同抽象层级上表述。
- 声明式的「底座」是命令式：Vue / React 让你写模板是声明式的，但**框架内部仍然是命令式地操作 DOM**。声明式的价值，正是把命令式细节封装起来，让你不必重复写。

### 前端同一需求的两种写法
| 需求 | 命令式 | 声明式 |
| --- | --- | --- |
| 显示一个值 | `el.textContent = x` | `{{ x }}` / `{x}` |
| 条件渲染 | `if (x) el.append(...)` | `v-if` / `{cond && <C/>}` |
| 列表 | 手动 `for` + `appendChild` | `v-for` / `map` |
| 路由跳转 | 手动改 `location` | `<RouterLink>` / `router.push` |

### 反直觉的边界例
判范式看「**表达方式**」，不是看是不是函数：
- `arr.map()` 返回**新数组**、不改原数据 → 声明式风格
- `arr.sort()` / `arr.forEach()` **原地修改** → 命令式风格
- CSS 用选择器描述「什么样」→ 声明式；用 JS 动画逐帧改样式 → 命令式

### 权衡
- 声明式：可读、可维护、可预测、易组合；代价是**控制粒度、调试、极致性能优化更难**
- 命令式：控制力强、能精细调优；代价是状态容易失控、重复代码多

### 常见混淆
- **声明式 ≠ 函数式**：函数式是声明式风格的重要来源，但声明式不限于函数式（SQL / HTML / CSS 都不是函数式，却都是声明式）。

## 我的理解 / 类比
命令式像**手把手写菜谱的每一步**（切、下锅、翻炒、出锅），声明式像**点一道菜**（「我要番茄炒蛋」）。点菜时你不管后厨怎么炒，但后厨终究要按命令式的步骤做——声明式只是把命令式藏到了你不必看见的层。
