# Sass 变量与原生 CSS 变量的区别

## 一句话定义
Sass 变量（`$x`）是**编译期**的纯文本替换，原生 CSS 变量（`var(--x)`）是**运行时**的真实变量——前者写死在产物里，后者能被 JS 读写、随级联动态变化。

## 用于解决什么问题
用 $primary 定主题色，运行时想切换只能重新编译，JS 里 setProperty 根本摸不到它；等要做暗色模式或用户自定义色，整份样式得推倒重写成 var()。

## 要点
| 维度 | Sass 变量 `$x` | 原生 CSS 变量 `var(--x)` |
|---|---|---|
| 生效时机 | 编译期，构建时替换 | 运行时，浏览器求值 |
| 能否被 JS 改 | ❌ 不行（产物里已无 `$x`） | ✅ `el.style.setProperty('--x', v)` |
| 级联 / 继承 | 无，按代码块 `{}` 词法作用域 | ✅ 遵循 CSS 级联，可继承、可覆盖 |
| 主题切换 | 需重新编译 | ✅ 改 `:root` 或 `data-theme` 即可 |
| 媒体查询内变化 | 不行（编译期已定） | ✅ 可响应 |

- **工程实践**：常把两者结合——用 Sass 变量定义设计令牌，再把它赋值给 CSS 变量（`--primary: #{$brand}`），既享受编译期统一管理，又保留运行时动态能力。
- **踩坑**：想在 JS 里改主题色却用了 Sass 变量，会发现根本拿不到——这是最典型的误用。

## 我的理解 / 类比
Sass 变量像"印刷前的模板填字"，印出来就固定了；CSS 变量像"屏幕上实时显示的字段"，随时能改。需要动态 / 交互 / 主题，用 CSS 变量；纯静态设计令牌，Sass 变量更省事。
