# 断点变体

## 一句话定义
断点变体是原子化 CSS 里「按视口（或容器）宽度条件应用工具类」的前缀语法，框架据此自动生成 `@media` 查询，无需手写媒体查询。

## 用于解决什么问题
每加一处响应式都要手写一个 `@media` 块，断点值散落在几十个文件里；想统一调整一个值只能全局搜索替换，漏掉的规则就和整体布局对不上。

## 要点

### mobile-first：`sm:` 是「及以上」，不是「小屏」
两者都遵循移动优先：不带前缀的类在所有屏幕生效，断点前缀表示「达到该断点**及以上**」才覆盖。

| 断点 | 视口宽度 | 生成的 CSS（Tailwind v4 写法） |
| --- | --- | --- |
| `sm` | ≥ 640px | `@media (width >= 640px)` |
| `md` | ≥ 768px | `@media (width >= 48rem)` |
| `lg` | ≥ 1024px | `@media (width >= 64rem)` |

典型用法（移动端 `text-xl`，≥640px 升级为 `text-4xl`）：

```html
<p class="text-xl sm:text-4xl font-bold text-white">{{ item.title }}</p>
```

- 覆盖关系由生成 CSS 的顺序决定（框架按断点排序输出），**与 HTML 中类名书写顺序无关**。
- 想表达「小屏」要写成不带前缀的基础类，再用断点类向上覆盖——不要试图用 `sm:` 表示小屏。

### 「小于断点」：UnoCSS `lt-sm:` vs Tailwind `max-sm:`
| | UnoCSS | Tailwind |
| --- | --- | --- |
| 写法 | `lt-sm:`（less than） | `max-sm:` |
| 生成 CSS | `@media (max-width: 639.9px)` | `@media (width < 640px)` |
| 边界 640px | ❌ 不含 | ❌ 不含 |

- 两者边界语义一致（都不含断点值本身）；UnoCSS 用「断点值 − 0.1px」实现。
- `lt-*` 前缀源自 Windi CSS 的 `<sm:`（`<` 容易与 HTML 冲突，UnoCSS 改名为 `lt-`，官方文档有对照表）。UnoCSS 同家族还有 `at-sm:`（仅该断点区间）、`gt-sm:`（greater than）。
- **Tailwind 没有 `lt-*` 前缀**。在「Tailwind 项目」里看到 `lt-sm`，该项目实际用的是 UnoCSS（或 Windi）。

### `@sm:`：同一写法，两边含义不同（易踩坑）
| 写法 | Tailwind | UnoCSS |
| --- | --- | --- |
| `@sm:` | **容器查询**：按父容器宽度（父元素需加 `@container`），与视口无关 | **显式媒体查询**：等价于 `sm:`（视口 ≥640px） |
| `~sm:` | 无此写法 | 容器查询变体 |

```html
<!-- Tailwind：父容器 ≥448px 时横排，与窗口宽度无关 -->
<div class="@container">
  <div class="flex flex-col @md:flex-row">...</div>
</div>
```

> 常见疑问：以冒号开头的 `:sm:` 不是两家任何一家的标准变体写法，多半是把 `@sm:` 或 `sm:` 误记/误读。

## 我的理解 / 类比
- 视口断点像「楼层电梯按钮」：`sm:` 是「二楼及以上都算」（开区间向上），`lt-sm:` / `max-sm:` 是「只有一楼」（不含二楼本身）。
- `@sm:` 是「同名按钮装在两栋楼里」：Tailwind 楼里它按**你所在的房间大小**（容器）触发，UnoCSS 楼里它按**大楼整体高度**（视口）触发——看到 `@` 先确认在哪个框架里。
