# 类型化路由

## 一句话定义
把每条路由的「名字 / 路径 / 参数」抽成一张编译期类型映射表，让 `useRoute()` 的返回值、`router.push()` 与 `<RouterLink>` 的目标都受 TS 检查——参数名写错、路由名不存在，编码时当场报错。

## 用于解决什么问题
路由名或路径改动时，编译器无法标出哪些 `push` / `<RouterLink>` 还指着旧名字，只能全局搜索字符串，漏改的那处要等用户点到才 404。

## 要点

### 它解决什么问题
- 手写 routes 时，`params` 的名字、类型、是否可选全靠人脑记；把 `params.id` 写成 `params.userId`，编译器一无所知。
- 类型化路由把每条路由的信息抽成类型映射表，交给 TS 检查。

### 两种启用方式
1. **文件式路由（推荐，自动生成）**：`vue-router/vite`（Vue Router 5 内置；旧项目用 unplugin-vue-router）→ 启动 dev server 生成 `typed-router.d.ts`（内含 `RouteNamedMap`）→ 加入 tsconfig 的 `include`，并设 `"moduleResolution": "Bundler"`。
2. **手动配置**：自己定义 `RouteNamedMap`（每条用 `RouteRecordInfo<Name, Path, ParamsRaw, Params, ChildrenNames>`），再 `declare module 'vue-router' { interface TypesConfig { RouteNamedMap: RouteNamedMap } }`。官方明说这很繁琐、易错，只在前一方式不适用时使用。

### 怎么取「有类型」的路由（三种写法，推荐最后一种）
```ts
useRoute() as RouteLocationNormalizedLoaded<'/study/[id]'>  // ① 断言：不含子路由类型，不推荐
useRoute<'/study/[id]'>()                                    // ② 泛型：含子路由，但无自动补全
useRoute('/study/[id]')                                      // ③ 传路径/名字：补全 + 含子路由类型（推荐）
```
- ③ 的返回值按该路由（含其子路由）类型化，`route.params.id` 直接推成 `string`。
- 开启 Volar 插件 `vue-router/volar/sfc-typed-router` 后，页面组件里的 `useRoute()` / `$route` 会**按当前页面自动**类型化，连 ③ 的参数都不用写。

### 路由名也是类型的一部分
- 类型映射表的 key 就是路由的 `name`。文件式路由默认用**文件路径**当名字（`pages/study/[id].vue` → `/study/[id]`），可用 `definePage({ name: 'study-by-id' })` 或 SFC `<route>` 块改成可读名。
- 类型化后 `router.push({ name })`、`<RouterLink :to="{ name }">` 的 `name` 同样受检查、能补全。

### 手写 helper（`RouteParams`）为什么不等价
```ts
import type { RouteParams } from "vue-router"
export function useRouteParams<P extends RouteParams>() {
  const route = useRoute()
  return route.params as P
}
```
- `RouteParams` 本身是**按路由名取参数**的泛型：`RouteParams<Name extends keyof RouteMap> = RouteMap[Name]['params']`。上面不传名字 → 默认成 `keyof RouteMap`，退化为「所有路由参数的联合」，约束很松。
- `route.params as P` 是**无校验断言**：`P` 由调用者随便给，编译器无法保证它与当前路由匹配——参数名写错照样通过。它只是「把已知类型手动贴上去」。
- 已经配置了类型化路由时，直接用 `useRoute('/study/[id]').params` 即可，不需要这个 helper。

## 我的理解 / 类比
手写路由像「凭记忆报路径」；类型化路由像给每条路由立了档案卡，编辑器负责核对暗号——参数名写错、路由名不存在，当场被拦下。三种写法是「翻档案的三种姿势」，`useRoute('/study/[id]')` 既补全又带全子档案。
