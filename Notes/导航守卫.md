# 导航守卫

## 一句话定义
在路由"跳转前 / 跳转中 / 跳转后"插入钩子，用来放行、取消或重定向导航；常用于登录鉴权、权限控制、数据预取。

## 用于解决什么问题
不拦的话，未登录用户直接打开 `/admin` 照样能看到页面；只能在每个页面组件里重复判断登录态，加载完再跳走，中间还会闪一下受保护内容。

## 要点
- **三类守卫**：
  - 全局：`router.beforeEach`（前置）、`router.beforeResolve`（解析，确认前、异步组件解析后）、`router.afterEach`（后置钩子，无 next、不改导航）。
  - 路由独享：`beforeEnter`（写在路由记录上，只在进入该路由时触发，不响应同路由 params/query/hash 变化）。
  - 组件内：`beforeRouteEnter`（不能访问 `this`，可通过 `next(vm => …)` 拿实例）、`beforeRouteUpdate`（组件复用时）、`beforeRouteLeave`（离开前，常用于未保存提醒）。
- 返回值（推荐写法，不用 next）：`false` 取消导航；一个路由地址（如 `{ name: 'Login' }`）重定向；不返回 / 返回 `true` 放行。
- ⚠️ 旧版 `next` 第三个参数**仍支持但易错**：必须保证每个守卫里 `next` 只被严格调用一次（多次调用 / 漏调用都会出问题）。
- ⚠️ `beforeEnter` 的守卫**只应用在目标路由上**，重定向路由本身不加守卫（见 [[路由重定向与别名]]）。
- **完整导航解析顺序**（12 步）：触发 → 失活组件 `beforeRouteLeave` → 全局 `beforeEach` → 复用组件 `beforeRouteUpdate` → 路由配置 `beforeEnter` → 解析异步组件 → 激活组件 `beforeRouteEnter` → 全局 `beforeResolve` → 导航确认 → 全局 `afterEach` → DOM 更新 → `beforeRouteEnter` 的 `next` 回调执行。
- 登录拦截经典写法：
  ```ts
  router.beforeEach((to, from) => {
    if (!isAuthenticated && to.name !== 'Login') return { name: 'Login' }
  })
  ```

## 我的理解 / 类比
像机场安检：全局前置是"总安检口"、路由独享是"某登机口的二次核验"、组件内离开守卫是"登机前确认你没落东西"。一道道过，任何一道说"不行"就拦下。
