# 响应式图片

## 一句话定义
响应式图片是让浏览器**自己挑**该下载哪张图：按设备尺寸、分辨率（DPR）以及支持的格式自动选择最划算的候选资源，而不是由作者写死一个 `src`。

## 用于解决什么问题
只给一个 `src` 时，手机也得下载为桌面准备的大图，白白拖慢首屏；想按设备换图只能靠 JS 猜 UA，既拿不到 DPR，也容易在换机型时挑错。

## 要点

### 它要解决的两个经典问题
| 问题 | 描述 |
| --- | --- |
| **resolution switching**（分辨率切换） | 同一张图、不同分辨率：大屏需要更大更清晰的图，小屏没必要为它浪费流量；而栅格图被放大超过固有尺寸就会发虚 |
| **art direction**（艺术指导） | 不同屏幕需要不同**裁剪/构图**：窄屏要裁掉两侧、只留中间主体，而不是把整张图缩小 |

两者常被混为一谈，但解法不同：前者靠 `srcset` + `sizes`，后者靠 `<picture>`。

### resolution switching：srcset + sizes
```html
<img
  srcset="elva-fairy-480w.jpg 480w, elva-fairy-800w.jpg 800w"
  sizes="(width <= 600px) 480px,
         800px"
  src="elva-fairy-800w.jpg"
  alt="Elva dressed as a fairy" />
```

- **`srcset`** 是候选集合，逗号分隔；每一项 = **文件名** + 空格 + 该文件的**固有宽度**。注意宽度用 `w` 单位，**不是 `px`** —— `480w` 表示"这个文件本身宽 480 像素"。
- **`sizes`** 是**布局宽度提示**：告诉浏览器"在当前条件下，这张图实际会占多宽"。
- 浏览器拿「布局宽度 × 设备 DPR」算出**实际需要多少物理像素**，再从 `srcset` 里挑最划算的那张。
- **关键认知：选择权在浏览器，作者只给提示。** 同一段 HTML 在 dpr 2 的手机和 dpr 1 的桌面上会挑到不同的文件 —— 这正是它比写死 `src` 强的地方。
- `src` 是兜底（老浏览器或 `srcset` 都不可用时）。

### art direction 与格式切换：`<picture>` + `<source>`
```html
<picture>
  <source media="(width >= 800px)" srcset="wide.jpg" />
  <source media="(width >= 400px)" srcset="mid.jpg" />
  <img src="narrow.jpg" alt="…" />
</picture>
```

- `<source media="…">` 表达**不同屏幕布局给不同构图**（art direction）—— 这是 `srcset` 做不到的，因为它只能在同一张构图里换分辨率。
- `<source type="image/avif">` 这类写法用于**格式优先级**（按浏览器支持的格式挑选）。
- 注意最后那个 `<img>` 不是装饰：`<picture>` 只是"候选来源容器"，**实际渲染与无障碍语义仍由 `<img>` 承担**（`alt`、尺寸、样式都写在它上面）。

> 本节 `srcset`+`sizes` 示例与语义来自 MDN 指南原文；`<picture>` 的示例是**机制示意**。

### 与「移动端适配」的关系：正交维度
本卡是 [[移动端适配]] 那张框架卡里的**正交维度**：

- `vw` / `rem` / 断点解决的是「**盒子多大**」；
- `srcset` / `sizes` 解决的是「**图多清晰、下多大**」。

两者互不替代：盒子比例算得再准，图片给了错的分辨率，结果要么糊、要么白烧流量。

## 我的理解 / 类比
- `src` 是「只带一件衣服出门」；`srcset` + `sizes` 是「几件都带上，让浏览器按当天的天气（视口 + DPR）自己挑」。
- `<picture>` 是「按场合换整套穿搭」—— 换的不是尺码，而是**裁剪与版式**。
