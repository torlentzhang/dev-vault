# 端到端测试工具

## 一句话定义
e2e 工具用来自动驱动真实浏览器、走完一条完整用户路径。当前主流是 **Cypress** 与 **Playwright**，主要差别在**浏览器覆盖范围**和**运行位置**。

## 用于解决什么问题
手工点一遍上线前的关键流程既慢又漏；而单元与集成测试都碰不到真实浏览器里的渲染、路由、网络与存储行为。

## 要点

### Cypress
- 测试代码**跑在浏览器里**：官方原文 *Cypress tests run inside of the browser! … your test code is being evaluated inside the browser. Test code is not evaluated in Node*，且不走对象序列化 / JSON wire protocol
- 浏览器范围：Chrome 系列（含 Edge）、Firefox；**WebKit 为 experimental**（需开 `experimentalWebKitSupport` 并装 playwright-webkit），官方原文 *Cypress currently supports Chrome-family browsers (including Edge and Chrome for Testing) and Firefox, plus experimental WebKit*
- **品牌版 Safari 驱动不了**：官方解释是 Apple 不在所有平台提供 Safari 的自动化，因此 *testing against WebKit is the practical way to validate how your app behaves in Safari*
- 官方支持最新 3 个主版本的 Chrome / Firefox / Edge

### Playwright
- 一套 API 驱动三种引擎：Chromium、Firefox、WebKit
- 自带官方 test runner 与内置 `expect` 断言，可用 projects 把同一份 spec 分别跑在三引擎上
- 同样**不是品牌版 Safari**：官方原文 *Playwright doesn't work with the branded version of Safari since it relies on patches*，支持的是 WebKit 构建
- 迁移口径：官方 Migration 导航只覆盖 Protractor / Puppeteer / Testing Library，**没有 from-Cypress 迁移页**；反倒是 Cypress 官方提供了 Playwright→Cypress 的迁移指南，并说明两者可在同一仓库共存

### nightwatch
基于 Node.js、走 W3C WebDriver 协议的 e2e 框架，当前稳定大版本 v3（文档 3.16.0），由 BrowserStack 开源项目持续维护，官方未见「维护模式 / 不再推荐」类表述。但主流社区选择已集中在前两家。

### 怎么选
- 要**跨三引擎（尤其含 WebKit）**、或需要官方 test runner 与并行 → **Playwright**
- 主要跑 Chrome 系、看重「测试就在浏览器里」的直观调试模型 → **Cypress**
- 已有 WebDriver 基础设施、或要驱动真机原生 App → **nightwatch**

## 我的理解 / 类比
Cypress 像**把自己搬进房间一起住**：和被测应用同处一个浏览器，看得见里面的一切，但也被这间房的墙限制住。
Playwright 像**从屋外遥控三台不同的机器**：站在屋外统一下指令，所以三台都能开，只是隔着一层。
