# 媒体查询

## 一句话定义
`@media` 是 CSS 原生的**条件规则**：媒体查询成立时，其中的样式才生效 —— 视口断点（响应式布局）就是它的主战场。

## 要点

### 基本语法与媒体类型
一个媒体查询 = **可选的媒体类型** + 任意个**媒体特性表达式**（每个必须带括号），中间用逻辑运算符组合：

```css
@media screen and (width >= 900px) {
  article { padding: 1rem 3rem; }
}
```

- **媒体类型**只剩三个：`all` / `print` / `screen`。类型可省略（隐含 `all`），**唯一例外是用 `only` 时必须写类型**。CSS2.1 与 Media Queries 3 的 `tty` / `tv` / `projection` / `handheld` / `braille` / `embossed` / `aural` 已在 **Media Queries 4 弃用**，不要再用。
- 媒体查询**大小写不敏感**；**涉及未知媒体类型的查询恒为 false**。
- 一个查询为真 ⟺ 媒体类型（若写了）匹配当前设备 **且** 所有特性表达式都为真。
- 同一套媒体查询还能用在 `@import`、HTML 的 `media=` / `sizes=` 属性上；JS 侧用 `window.matchMedia()` 读取。
- 顺带一个反直觉事实：`<link media="…">` 即使查询**不成立，样式表仍然会被下载**（只是优先级极低），不是「不匹配就不下载」。

### 逻辑运算符（以 MDN 原文为准）
| 运算符 | 作用 |
| --- | --- |
| `and` | 把多个媒体特性串成一个查询（也用于把特性与媒体类型连起来），**全部为真**才成立 |
| `,`（逗号） | 查询**列表**：任意一个为真即生效，等价于逻辑 `or` |
| `or` | 与逗号等价，**Media Queries Level 4 新增** |
| `not` | 取反；在逗号列表里只取反**它所在的那一个**查询。Level 3 中 `not` 不能只取反单个特性表达式，只能取反整个查询 |
| `only` | 整个查询匹配才应用，用来**挡住不认识媒体特性的老浏览器**（不写 `only` 时，老浏览器会把 `screen and (width <= 500px)` 读成 `screen`，从而在所有屏幕上生效）。现代浏览器上它**没有效果**；**用了它必须写媒体类型** |

### 两种断点写法：`min-` / `max-` 前缀 与 范围语法
```css
@media (min-width: 30em) and (max-width: 50em) { /* … */ }   /* 前缀写法 */
@media (30em <= width <= 50em) { /* … */ }                   /* 范围语法（Level 4） */
```

- **区间包含性（易错）**：`min-` / `max-` 前缀与 `>=` / `<=` **都是闭区间（含边界值）**；要排除边界值必须显式写 `<` / `>`。MDN 原文：「The range comparisons above are inclusive.」
- 范围语法更简洁，还能**链式**表达区间（`30em <= width <= 50em`），意图比「`min-` 与 `max-` 拼起来」更清楚。
- **兼容性（MDN BCD 数据）**：范围语法 Chrome 104 / Firefox 102 / Safari 16.4（BCD 未单列 Edge，随 Chromium）；`or` 关键字 Chrome 104 / Firefox 64 / Safari 16.4。而 `min-` / `max-` 前缀随 `width` 这类 range 特性**从早期就支持**（Chrome 1 / Firefox 2 / Safari 3）。
  → 结论：新项目可以写范围语法；**必须兼容更老浏览器时写 `min-` / `max-` 前缀**，别为了「更现代」在兼容要求高的项目里用范围语法。

### `mobile-first`：方向比数值更重要
移动优先 = **基础样式写给最小屏，再用 `min-width` 逐级向上覆盖**：

```css
.card { display: block; }                                    /* 基础：最小屏 */
@media (min-width: 40rem) { .card { display: flex; } }        /* 往上第一级 */
@media (min-width: 64rem) { .card { gap: 2rem; } }            /* 再往上 */
```

为什么它能成立，是**两条层叠规则**叠加的结果：

1. **媒体查询不参与特异性计算** —— 特异性只由**选择器**算出（MDN：浏览器先确定层叠来源与重要性，**之后**才考虑特异性），`@media` 只是条件分组，不会给里面的规则加权重。
2. **同等特异性下，后出现的声明获胜** —— MDN 层叠排序第 5 条 *Order of appearance*：匹配选择器特异性相同时，「the last declaration in the style block wins」。

合起来就是一条**必须记住的操作规则**：

> **断点要从小到大、从上往下写。** 覆盖的胜负由 **CSS 源码顺序**（同等特异性下）决定，而不是「哪个查询更严格」；把大断点写在小断点前面，就会让大断点的样式被后面的小断点覆盖掉。

⚠️ 别把这条与 **HTML 里类名的书写顺序**混起来 —— 那条是 [[断点变体]] 里记的规则（框架按断点排序生成 CSS，所以 HTML 里类名怎么写都不影响），说的是**框架产物**的顺序，不是这里的手写源码顺序。

### 断点值从哪来
**常见断点不是标准**，只是各家设计系统的默认值。以 Tailwind CSS v4 为例，其默认主题变量（官方 `theme.css`）为：

| 名称 | 值 | ≈ px |
| --- | --- | --- |
| `sm` | `40rem` | 640 |
| `md` | `48rem` | 768 |
| `lg` | `64rem` | 1024 |
| `xl` | `80rem` | 1280 |
| `2xl` | `96rem` | 1536 |

（「≈ px」是按根字号 16px 换算的近似；v4 把断点定义在 **rem** 上。）

**这里有个关键事实**：媒体查询里的相对单位**以初始值为基准，不受页面样式影响**。Media Queries 4 规范 §1.3 原文：

> Relative length units in media queries are based on the initial value, which means that units are never based on results of declarations. For example, in HTML, the `em` unit is relative to the initial value of `font-size`, defined by the user agent or the user's preferences, **not any styling on the page**.

所以**劫持根字号（[[rem 适配]] 里的 `calc(100vw/10)`、flexible）不会平移这些 rem 断点** —— 断点仍按浏览器默认字号（通常 16px）换算。这也说明断点值与页面内 rem 布局是两套互不干扰的尺子。

实践上，断点应按**内容断点**（布局开始变得难看的那个宽度）自定，而不是照抄某一家的数值 —— 这是实践建议，非规范结论。

### 媒体查询的边界
- 它判断的是**视口**（以及用户代理、输出设备、环境）。规范原话：「Media queries are (almost) always independent of the contents of the document」—— **不看元素所在的容器**：同一个组件放进侧栏还是主区域，媒体查询的结论不变。**组件级适配归 [[容器查询]]。**
- 它**查不到「元素自身有多宽」** —— 媒体特性里没有这样的项。
- 它管的不只是宽度：用户偏好类查询也走 `@media`，如 `prefers-color-scheme`（Chrome 76 / Firefox 67 / Safari 12.1）、`prefers-reduced-motion`（Chrome 74 / Firefox 63 / Safari 10.1）。
- **别用 `device-width`**：`device-width` / `device-height` / `device-aspect-ratio` 在 Media Queries 4 已弃用（MDN BCD 标 `deprecated`），断点一律用 `width`。
- 若某特性不适用于当前设备，涉及它的表达式**恒为 false**。

## 我的理解 / 类比
- `@media` 是「按**整栋楼**的尺寸决定装修方案」；[[容器查询]] 是「按**你这个房间**的大小决定装修方案」。同一套家具（组件）搬到大楼里任何位置，前者只看楼、后者只看房间。
- `min-width` 是电梯按钮式：不带前缀的基础样式是「一楼」，`min-width` 每加一级就往上一层 —— 所以基础样式必须写给最小的那一层。
- 顺序规则可以记成：**媒体查询不加砝码，只排队**。特异性是砝码，`@media` 不是砝码；同等砝码下按排队先后（源码顺序）定胜负，后面的压在前面身上 —— 所以队伍必须从最小屏排到最大屏。
