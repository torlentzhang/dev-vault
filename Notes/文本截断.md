# 文本截断

## 一句话定义
文本截断是**三件独立的事拼起来**的：**制造溢出 → 裁剪溢出 → 在裁剪处表达「还有更多」**；CSS 里单行靠 `text-overflow`、多行靠 `-webkit-line-clamp`、想要渐隐则用 `mask-image`。

## 用于解决什么问题
标题、列表项、卡片描述经常放不下又不该撑破布局：不许换行、不许撑高，还要让用户知道「后面还有」。不处理时文字会把容器挤变形，或者被硬切一半显得像 bug；手工用 JS 量高度截字符串则要处理字体加载、窗口缩放、中英文混排，成本远高于收益。

## 要点

### 三件事必须分开看（第一落点）
```text
① 制造溢出  →  ② 裁剪掉溢出部分  →  ③ 在裁剪处表达「还有更多」
   nowrap        overflow: hidden       text-overflow / line-clamp / mask
```
MDN 对 `text-overflow` 的原话是：它 **doesn't force an overflow to occur** —— 它**不制造溢出**，必须由别的属性把溢出造出来。

> **记法**：`nowrap` 是把文字**撑出**盒子，`overflow` 是把撑出去的部分**剪掉**，`text-overflow` 是在剪刀口上**贴个省略号**。

只写 `overflow: hidden` + `text-overflow: ellipsis` 而不写 `white-space: nowrap` 时，文字正常换行、**根本不存在水平溢出**，因此永远不会有省略号。这是「写了没反应」最典型的根因。

### 单行截断
```css
.one-line {
  overflow: hidden;        /* 或 clip / auto / scroll —— 只要不是 visible */
  white-space: nowrap;     /* 制造单行溢出 */
  text-overflow: ellipsis; /* 在裁剪处画省略号 */
}
```
- `overflow` **不要求恰好是 `hidden`**，规范只要求「不是 `visible`」。
- `white-space: nowrap` 是**常规手段**：一个不可断行的超长单词同样会溢出并出省略号，但要的是「单行」就必须写它。
- `text-overflow` 的 **Applies to 是 block container**，要写在真正承载这段文本的块级元素上。
- 规范原文限定：只影响在 **inline 方向**溢出块容器的内容。

### 多行截断：`-webkit-line-clamp`
```css
.clamp-2 {
  display: -webkit-box;          /* 硬依赖 */
  -webkit-box-orient: vertical;  /* 硬依赖 */
  -webkit-line-clamp: 2;
  overflow: hidden;              /* 官方只说「大多数情况想设」，实操当硬依赖 */
}
```
- `display: -webkit-box`（或 `-webkit-inline-box`）+ `-webkit-box-orient: vertical` 是**官方明文写的共依赖**（MDN："only works in combination with…"；规范 §5.1.1 Legacy compatibility）。
- `overflow: hidden` 官方表述为「大多数情况下你会想设」——不设则内容不被真正裁剪、省略号仍显示，视觉上会露馅。
- 各引擎起始版本：Chrome 6 / Edge 79 / Firefox 68 / Safari 5 / Safari iOS 4.2。

### ⚠️ 标准 `line-clamp` 目前还**不能**用
- **标准无前缀 `line-clamp`（CSS Overflow L4）尚未进入 Baseline**：Chrome / Edge / Firefox / Safari 及移动端**全部 Not supported**，MDN 页首标注 “Limited availability — not Baseline”；Chromium issue `40336192`、Firefox `bugzil.la/1540681` 至今仍是开放缺陷。
- 标准版**写法更简单**：适用于块容器（多列容器除外），常规 `display` 即可，**不需要** `-webkit-box` 那一套——`-webkit-box` 共依赖只写在规范的 **legacy 前缀**小节里。即**规范已设计好更好的写法，但浏览器还没实现**。
- 同属该特性集的 `block-ellipsis`（语义化的多行省略）同样未实现，MDN 连属性页都没有。
- **别被 caniuse 误导**：它那条 “CSS line-clamp” 讲的是**带前缀**的 `-webkit-line-clamp`；带前缀版虽被长期广泛支持，但**不被计为 Baseline**，因为 Baseline 追踪的是标准属性。

### 渐隐式截断：`mask-image`
不想要「…」、让文字自然淡出时：
```css
.fade {
  max-height: calc(1.5em * 3);   /* 按自身 line-height 估算行高 */
  overflow: hidden;
  mask-image: linear-gradient(to bottom, #000 60%, transparent 100%);
}
```
- `mask-image` 已是 **Baseline widely available**，MDN 标注 “available across browsers since December 2023”。
- ⚠️ 看细数字：无前缀写法 **Chrome 是 120 起**（2023-12），Safari 15.4、Firefox 53。要兼容 2023 年底之前的 Chromium 内核，**仍需补 `-webkit-mask-image`**（前缀写法自 Chrome 1 / Safari 4 就存在）。
- 取舍：行数是**算**出来的（`max-height` 估算），不是浏览器按行切；行高不固定或字体回退时可能露出半截行。要精确按行数，它不如 `line-clamp`。

### `max-height` 硬截断
`max-height` + `overflow: hidden` 最不挑环境，代价是**没有省略号、文字被拦腰切断**。适合背景图上的装饰性文字，不适合正文；常作方案 3 的底座（`max-height` 限高 + `mask` 收口）。

### 坑：`overflow: clip` vs `overflow: hidden`
做纯截断时 `clip` 语义更准，但三者差异会影响布局：
| | `overflow: hidden` | `overflow: clip` |
| --- | --- | --- |
| 滚动容器 | 是（只是没滚动条） | **不是** |
| 程序化滚动 | 仍可（`scrollLeft` / `scrollTo()` / tab 聚焦） | **完全禁止** |
| 新格式化上下文 | 创建 | **不创建**（需配 `display: flow-root`） |

⚠️ 若原本依赖 `overflow: hidden` 建立 BFC 来清浮动，换成 `clip` 会**破坏原有布局**。

### 坑：Flex / Grid 子项里省略号失效 → 先试 `min-width: 0`

**已核实的机制事实**：普通块级元素的 `min-width: auto` 解析为 `0`；但 **flex items / grid items 的 `auto` 用 min-content 尺寸**，除非该子项本身是 scroll container（那才是 0）。`flex-shrink: 1` 与 `min-width` 是两套独立规则，**后者能否决前者**。

**按机制推得**（MDN 无此场景明文）：省略号的前提是「**文字比盒子宽**」，而 flex 默认恰好让盒子跟着文字变宽。

```html
<div class="row">                    <!-- 宽 300px -->
  <div class="title">今天天气非常好我们一起去公园散步吧</div>   <!-- flex: 1 -->
  <div class="icon"></div>           <!-- 宽 40px，不收缩 -->
</div>
```
```css
.row   { display: flex; width: 300px; }
.title { flex: 1; overflow: hidden; white-space: nowrap; text-overflow: ellipsis; }
```

跟着宽度走一遍：

1. 文字写了 `nowrap`，**不许断行**，整行量出来约 **400px**。
2. `.title` 的 `min-width: auto` = min-content = **400px**（「一行都不许断」意味着 min-content 就是整行的宽度）。
3. flex 因此**压不动** `.title`：整行变成 400 + 40 = **440px，撑破了 300px 的容器**。
4. 而 `.title` 自己被撑到 400px，文字也正好 400px → **文字不比盒子宽 → 没有溢出 → 没有省略号**。

加上 `min-width: 0` 后：

```css
.title { flex: 1; min-width: 0; /* 其余不变 */ }
```

5. 下限被拆掉，`.title` 肯缩了 → 实际宽度 **260px**（300 − 40）。
6. 文字 400px **比盒子 260px 宽** → 溢出 140px → `overflow: hidden` 剪掉 → `text-overflow` 贴上「…」。

> **一句话**：flex 默认让盒子「**跟着文字变宽**」，于是文字永远不比盒子宽，省略号也就永远没机会出现；`min-width: 0` 就是把这条默认行为关掉。

Grid 同理，只是写在轨道上：`1fr` 隐含 `minmax(auto, 1fr)`，要能缩到 0 需写 `minmax(0, 1fr)`（见 [[Grid 布局]]）；块轴方向对应 `min-height: 0`。

> ⚠️ 文档存在**张力**：MDN 说 `overflow: hidden` 的盒子**是** scroll container，按字面它自动最小尺寸应为 0，那上面第 2 步就不该发生、也就不需要 `min-width: 0`；MDN 未解释该矛盾。实操上它几乎零成本、加了不亏，这也是 `min-w-0` 在原子化 CSS 项目里高频出现的原因。

## 我的理解 / 类比
把文本装进固定宽的盒子里，三样东西缺一不可：
- `white-space: nowrap` = **不许折行**，文字只能一路向右伸出盒外；
- `overflow: hidden` = **一把剪刀**，沿盒子边缘把伸出去的部分剪掉；
- `text-overflow: ellipsis` = 在**剪刀口上贴一个「…」**。

不伸出去就没得剪；不剪就露在外面；剪了不贴标签，读者不知道后面还有内容。

`min-width: 0` 对付的是另一件事——「**盒子不肯比文字窄**」。flex 子项默认按 min-content 给自己划一条下限，写死 `nowrap` 时这条下限就等于整行文字的宽度，盒子因此永远和文字一样宽，剪刀永远碰不到东西。`min-width: 0` 拆掉下限，盒子才肯真正变窄，文字才「比盒子宽」，省略号才有出场机会。
