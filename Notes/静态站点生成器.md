# 静态站点生成器（SSG）

## 一句话定义
SSG（Static Site Generator）是在构建时把 Markdown、组件等源码预渲染成一组静态 HTML/CSS/JS 文件的工具；产物不依赖常驻服务端，直接交给静态托管即可。

## 用于解决什么问题
博客、文档、官网这类「每个用户看到的内容相同、更新靠重新发布」的站点，如果每次请求都跑一遍服务端渲染，纯属浪费。SSG 把渲染提前到构建时，一次生成、反复分发，首屏和托管成本都更省。

## 要点

### 四个工具的定位

| 工具 | 定位 | 内容与组件 | 博客支持 | 适合 |
| --- | --- | --- | --- | --- |
| VitePress | Vite + Vue 驱动的内容型 SSG | Markdown 可嵌 Vue 组件 | 默认主题面向技术文档，无官方博客主题 | 技术文档、文档与博客混排 |
| Astro | 内容优先的 SSG，支持多框架 | Markdown / MDX，可混用 React、Vue、Svelte 组件 | 有官方博客教程、Content Collections、blog starter | 个人博客、长期内容站 |
| VuePress | Vue 3 的 SSG，打包器可用 Vite 或 Webpack | Markdown + Vue | v2 仍是 RC，不是稳定版 | 已有 VuePress 项目 |
| Hexo | 基于 Node.js 的博客框架 | Markdown 生成静态文件 | 主题系统成熟，换主题即换外观 | 纯博客、想快速套主题 |

### 博客选型判据
先看内容形态，再看技术栈：

- 文章为主、想快速上线 → Hexo
- 文章为主、想要现代内容管线并尽量少发 JS → Astro
- 技术笔记、文章里大量嵌 Vue 组件和代码演示 → VitePress
- 已有 VuePress 项目 → 继续用，不为换工具迁移

### 常见坑
- **VitePress 不是博客框架**：归档、标签、分页、RSS 没有官方实现，需要自定义主题或社区插件
- **Astro 的「默认无 JS」是默认剥离客户端 JS**，不是绝对零 JS；交互组件要显式加 `client:*` 指令才会水合
- **VuePress v2 仍是 RC**：新项目要接受预发布状态带来的升级成本
- **Hexo 主题是独立项目**：主题有自己的 `_config.yml`，换主题要迁移配置
- **SSG 只解决「HTML 何时生成」**：内容因人而异（登录态、个性化推荐）时仍要 SSR 或 ISR

## 我的理解 / 类比
SSG 像印刷厂：内容定稿后一次性印好，谁来都拿同一份，分发快、成本低；代价是改内容必须重新开机印刷（重新构建发布）。SSR 像现点现做，能按人下菜，但每单都要开火。
