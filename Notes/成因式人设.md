# 成因式人设

## 一句话定义

写人设时描述**这个表现是怎么来的**——从什么处境开始、他因此要什么、后来怎么定型，而不是罗列表面特征。成因能推导出多种外在行为，特征只能被逐个复述。

## 用于解决什么问题

按「喜欢喝酒、话不多、讨厌被同情」这样列出的人设，模型只能用最直白的方式把每条演一遍。几轮之后开始循环，角色从「有性格」退化成「在背设定」。

## 要点

### 两种写法：指定结果，还是给出成因

| 写法  | 例子                                     | 性质         |
| --- | -------------------------------------- | ---------- |
| 特征  | 他喜欢喝酒                                  | 直接指定结果     |
| 规则  | 别人提家里事他就讲路况                            | 条件指定结果     |
| 成因  | 他下岗后一直觉得自己不算数，只有后座有人、由他决定往哪走，他才觉得自己在做事 | 给出这个表现怎么来的 |

前两种是对结果的一次性指定，区别只在挂不挂条件。指定得再细，也只产出它自己。

**加条件不会让指定变成成因**，这是最容易误判的地方：把特征改写成「当 X 就做 Y」，看起来像流程，实际仍然是一次性指定。

两者把「具体」放在哪一头，正好相反：

```text
规则：抽象触发 + 具体反应    谁提家里事都一样，一律讲路况——反应被钉死，模型没有余量
成因：具体来源 + 抽象倾向    下岗、觉得自己不算数，落到「得有个位置」——长得出各种反应
```

### 成因是一条链

不是一句解释，是四段：

```text
起点   嘴唇厚
反应   被人笑过，觉得难看，自卑
需求   想让嘴唇显得薄一点
固化   抿嘴，做了十几年，成了下意识的动作
```

```text
起点   下岗，找不到活
反应   觉得自己不算数
需求   得有个位置，能由他决定点什么
固化   开出租，后座有人、由他决定往哪走；话多起来，一直开到现在
```

```text
起点   一个人住，夜里没人说话
反应   屋子太静，坐不住
需求   需要陪伴
固化   等不来人，拿酒把夜顶过去；十几年，不喝就睡不着
```

微动作和行为模式，生成方式是同一种：一个处境，一次反应，一个要的东西，然后时间把它变成了现在这样。

分开列是为了看清四段，实际写的时候起点和反应常常压成一句；需求与固化省不掉。

**固化那段写的是他实际做了什么**，不是他想要什么。有的是需求被直接实现——开出租，后座有人；有的是需求没被满足，拿别的东西顶上——等不来人，酒成了那个「在」。

### 只写中段，写出来的还是需求

需求是链的第三段，单独拿出来仍然成立，但它是通用的一环：谁都需要被人需要，谁都需要有人说说话。通用的东西推不出具体的人。

写「他需要陪伴」，模型会让他找人聊天、养猫、打电话；写完整条链，模型知道他要的不是聊天，是排解消遣——而这个位置最后被酒占了。

### 两个步骤

1. 把清单分两类：可推导的（性格、习惯）与不可推导的（口音、年代、职业）。后者推不出来，直接写，但压到最短。
2. 对可推导的，问「这个表现是怎么来的」，四段都要有落点：起点是什么，他当时怎么反应，他要解决什么，后来怎么定型。

### 常见混淆

- 成因不等于更长的特征。`他父亲开酒吧 / 十九岁开始喝 / 三十岁戒了` 写成故事口吻，仍然是清单。
- 「生活的重担」不构成成因。没有具体内容的因等于没写，只能渲染情绪，推不出行为。
- 形容词与特征、规则同属一类：都是在直接指定性格。「痴狂」指定得极窄，只剩两三种演法；「温柔」指定得极宽，宽到谁都能算，最后长成通用「好人」。所以形容词只适合当标签，真要立住还得回到成因。

## 我的理解 / 类比

写法是**说明书**，成因是**生平**。说明书列了什么就只能做什么，生平能推出没写进去的事。
