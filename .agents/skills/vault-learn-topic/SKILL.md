# vault-learn-topic

帮助用户把「偶尔听到的一个知识点」真正学会，学透后交棒 `vault-add-card` 完成落库。

本 Skill 只负责学习过程，不负责创建或修改卡片；模板、命名、MOC、索引等落库规则以 `vault-add-card` 与根目录 `AGENTS.md` 为准，此处不重复定义。

## 步骤

### 1. 调研核实（并行委托两个子代理）

本步骤由两件互不依赖的事组成：检索 vault 已有认知、核实知识本身。
两者在**同一轮并行**委托，主上下文只接收结论与证据，不接收检索过程。

**委托 A — vault 已有认知**

* 任务：检索 `Notes/`，判断是否已有相关卡片
* 返回：
  * 最相关的 1~2 张卡片的**完整内容**（保留 vault 原有术语与写法，用于对齐讲解风格）
  * 其余相关卡片：`卡片名` + 一句话说明关系
  * 可作为后续关联候选的邻近卡片
  * 明确结论：有 / 无相关卡片；没有就直说，不要牵强关联

**委托 B — 知识核实**

* 任务：按 `AGENTS.md` 第 4 条来源优先级核实知识本身
* 返回：逐条列出「结论 + 出处（URL / 文档位置） + 标注」
  * 标注统一使用 `AGENTS.md` 第 4 条的三个词：**已核实 / 存疑 / 未核实**
  * 只给结论不给出处的，一律按「未核实」处理
  * 委托提示词必须自带来源优先级要求，不假设子代理读过 `AGENTS.md`
  * 若检索通道不可用，直接回报「无法联网核实」，不得以记忆充当已核实

主上下文据此讲解：

* 输出时明确区分「已核实的事实」「存疑」「未核实」
* 未核实的内容不得作为定论输出
* 不把检索残渣（搜索列表、无关卡片、SEO 段落）带进讲解

**可省略的情形**（自行判断，不凑数）：

* 知识点属稳定且无争议的基础知识 → 可省委托 B，并在讲解中说明未联网核实
* 用户明确指向某张已有卡片 → 直接读取该卡片，不必为委托 A 起子代理

**不得委托**：讲解与检验理解必须在主上下文完成。

---

### 2. 讲解

* 先用一句话说清「它是什么、解决什么问题」，再展开机制与细节
* 使用类比和具体例子，不堆砌术语
* 区分「必须掌握的核心」与「可以以后再了解的细节」，不一次倾倒全部内容
* 详略随用户要求：用户要「快速了解」就给速览，要「深入」就给机制层

---

### 3. 检验理解

讲解完成后，确认用户真正吸收，而不只是看过：

* 请用户用自己的话复述，或向用户提 1~2 个关键问题
* 复述若有偏差，指出偏差、纠正、再次确认，直到用户表达准确
* 用户明确表示不需要检验时可跳过

---

### 4. 交棒落库

* 确认理解后，询问用户是否要总结成卡片，不擅自创建
* 用户同意后，调用 `vault-add-card` 完成落库；本 Skill 不直接写 `Notes/`
* 交棒时一并移交委托 B 的核实结论（含「已核实 / 存疑 / 未核实」与出处），供 `vault-add-card` 直接使用，不再重复核实
* 用户暂不存卡则正常结束

---

## 边界

* 围绕单一知识主题；用户追问出新的独立主题时，视为新主题重新走流程
* 不做 MOC 归位、索引同步、卡片命名判断——这些全部属于 `vault-add-card`
