# vault-learn-topic

帮助用户把「偶尔听到的一个知识点」真正学会，学透后交棒 `vault-add-card` 完成落库。

本 Skill 只负责学习过程，不负责创建或修改卡片；模板、命名、MOC、索引等落库规则以 `vault-add-card` 与根目录 `AGENTS.md` 为准，此处不重复定义。

## 目标深度：默认应用层

默认教「怎么用」，不教「怎么实现」：

| 档位 | 覆盖范围 | 启用条件 |
| --- | --- | --- |
| 应用层（默认） | 是什么、怎么用、适用 / 不适用场景、常见坑、影响「还能不能用」的版本信息 | 用户未指定 |
| 机制层 | 为什么这样设计、内部流程、方案本质差异 | 用户问「原理」「机制」「为什么」 |
| 源码层 | 具体实现、依赖选型、源码级默认值、版本演进 | 用户点名「源码」「实现」 |

查到更深 ≠ 讲更深：不在本档的内容不查、不讲、不落卡。

## 步骤

### 1. 调研核实（并行委托两个子代理）

本步骤由两件互不依赖的事组成：检索 vault 已有认知、核实知识本身。
两者在**同一轮并行**委托，主上下文只接收结论与证据，不接收检索过程。

**委托前**：在主上下文冻结本轮「应用断言清单」（3~6 条，写成可核实的问题，如「配置怎么写」「不配会怎样」「版本要求」），只把清单交给委托 B，清单外不查。

**委托 A — vault 已有认知**

* 任务：检索 `Notes/`，判断是否已有相关卡片
* 返回：
  * 最相关的 1~2 张卡片的**完整内容**（保留 vault 原有术语与写法，用于对齐讲解风格）
  * 其余相关卡片：`卡片名` + 一句话说明关系
  * 可作为后续关联候选的邻近卡片
  * 明确结论：有 / 无相关卡片；没有就直说，不要牵强关联

**委托 B — 知识核实**

* 任务：只核实**应用断言清单**上的条目，按 `AGENTS.md` 第 4 条来源优先级找官方出处
* 范围上限（必须写进提示词）：
  * 只读官方文档 / README 的用法、配置、API、限制章节
  * **不查实现**：不看源码、不核对文档与源码的默认值差异、不追依赖选型
  * **不追考据**：改名史、下载量、star 数、提交活跃度都不算应用结论；只有 deprecated、最低支持版本、兼容性这类影响「还能不能用」的信息才保留
  * 官方文档已写清即终点；清单外的发现不回报
  * 例外：某条应用结论必须看源码才能确认时，只取那一处，并注明「为确认 X 看了 Y」，仍只回报应用层结论
* 边界（必须写进提示词）：**只读核实**——不得为核实安装 npm 包、克隆仓库到本地或运行代码取结果；确认不了的直接回报「未核实」，不自行搭实验环境
* 返回：逐条对应断言，给「应用结论 + 出处（URL / 文档位置） + 标注」，不附机制细节
  * 标注统一使用 `AGENTS.md` 第 4 条的三个词：**已核实 / 存疑 / 未核实**
  * 只给结论不给出处的，一律按「未核实」处理
  * 委托提示词必须自带目标深度、来源优先级与上述只读 / 范围边界，不假设子代理读过 `AGENTS.md`
  * 若检索通道不可用，直接回报「无法联网核实」，不得以记忆充当已核实

主上下文据此讲解：

* 讲解开头用一句话说明本轮范围，用户可叫停或升档
* 只采用清单内的结论，清单外的发现不进入讲解
* 输出时明确区分「已核实的事实」「存疑」「未核实」
* 未核实的内容不得作为定论输出
* 不把检索残渣（搜索列表、无关卡片、SEO 段落）带进讲解

**可省略的情形**（自行判断，不凑数）：

* 知识点属稳定且无争议的基础知识 → 可省委托 B，并在讲解中说明未联网核实
* 用户明确指向某张已有卡片 → 直接读取该卡片，不必为委托 A 起子代理

**不得委托**：讲解与检验理解必须在主上下文完成。

---

### 2. 讲解

* 默认应用层：一句话说清「它是什么、解决什么问题」，直接落到怎么用、什么时候用、什么时候别用、常见坑
* 机制只在解释「为什么必须这么写」「不这么写会怎样」时补一句，够用就停
* 使用类比和具体例子，不堆砌术语
* 区分「必须掌握的核心」与「可以以后再了解的细节」，不一次倾倒全部内容
* 用户明确要求「深入 / 原理 / 源码」时才升档，只讲问到的那一段，讲完回到应用层

---

### 3. 检验理解

讲解完成后，确认用户真正吸收，而不只是看过：

* 请用户用自己的话复述，或向用户提 1~2 个关键问题
* 复述若有偏差，指出偏差、纠正、再次确认，直到用户表达准确
* 用户明确表示不需要检验时可跳过

---

### 4. 交棒落库

* 确认理解后，询问用户是否要总结成卡片，不擅自创建
* 用户同意后，调用 `vault-add-card` 完成落库；本 Skill 不直接写 `Notes/`
* 交棒时一并移交应用断言清单与对应核实结论（含「已核实 / 存疑 / 未核实」与出处），供 `vault-add-card` 直接使用，不再重复核实；机制层枝节不带入卡片
* 用户暂不存卡则正常结束

---

## 边界

* 围绕单一知识主题；用户追问出新的独立主题时，视为新主题重新走流程
* 不主动下潜：应用层能说清的，不往机制层、源码层追；用户没问的实现细节不查、不讲、不落卡
* 升档只对当前主题生效，不改变后续主题的默认档位
* 不做 MOC 归位、索引同步、卡片命名判断——这些全部属于 `vault-add-card`
